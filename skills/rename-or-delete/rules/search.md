# 参照の探し方

改名・削除の前に必ず読む。目的は「参照が無い」ことを示せる状態にすることで、検索した範囲と件数を後から説明できるようにする。

## 検索の範囲

**リポジトリ全体を対象にし、除外するのは依存と生成物だけにする。** アプリのソース配下だけを探すと、次の場所の参照が漏れる。

| 見落としやすい場所 | 例 |
| --- | --- |
| テスト・フィクスチャ | ユニットテスト、スナップショット、モックデータ |
| E2E シナリオ | セレクタ、URL、テストデータに書かれた名前 |
| ドキュメント | README、`docs/`、ADR、`CLAUDE.md` / `AGENTS.md` |
| 設定ファイル | ルーティング定義、ビルド設定、CI のワークフロー、リダイレクト設定 |
| 文字列リテラル | 動的 import のパス、`data-*` 属性、翻訳キー、ログのイベント名 |
| スタイル | クラス名、カスタムプロパティ、アセットへの `url()` |

除外してよいのは `node_modules`、ビルド出力、ロックファイル、生成されたコード（生成元を直すため）である。`git grep` を使うと、`.gitignore` 済みのものは自然に外れる。ただし、まだ `git add` していない新規ファイルも検索されない。作業中に追加したファイルがある場合は、`--untracked` を付けるか、下の `grep` を使う。

```bash
git grep -n -- '<name>'
# 未追跡の新規ファイルも含める場合
git grep -n --untracked -- '<name>'
# .gitignore 済みのファイルも含めて探す場合
grep -rn --exclude-dir=node_modules --exclude-dir=dist -- '<name>' .
```

## 名前の揺れ

1 つの対象が複数の表記で参照されていることがある。次の表記を個別に検索する。

- 大文字・小文字の違い（`UserCard` と `userCard`）
- 区切りの違い（`user-card`、`user_card`、`userCard`）
- パスとしての参照（`components/UserCard`、`./UserCard.tsx`、拡張子なし）
- 文字列を組み立てて作る参照（`` `icon-${name}` ``、`'user' + 'Card'`）

組み立て型の参照は検索で見つからない。対象が組み立てられうる命名（アイコン名、翻訳キー、ルート名など）なら、組み立てている側（テンプレート文字列、マップ、レジストリ）を探し、取りうる値を列挙して確かめる。

## 未使用 export を数えるとき

import 行の件数をそのまま参照数にしない。次のものが「使用中」として数えられてしまう。

- **Storybook の CSF**：`*.stories.*` は全コンポーネントを import するため、本番で未使用でも参照が残る。対象から外して数える
- **バレルファイルの再エクスポート**：`index.ts` の `export * from` / `export { X } from` は、それ自体は利用ではない。再エクスポート行は参照数から差し引き、バレルの先で使われているかを追う
- **名前空間 import**：`import * as M` の場合は、`M.X` の形で使われているかを別に検索する

## 「無い」と結論づける前に

「その導線は存在しない」「その実装は無い」と判断するときは、**定数のキー名ではなく値で確かめる**。定数のキー名は実態と食い違うことがある（`LEGACY_LIST` という名前の定数が現行の一覧画面を指している、など）。関連する定数の値（URL・パス・ID）を 1 件ずつ実際の遷移先や呼び出し先と突き合わせ、どれにも該当しないことを確かめてから結論を出す。

## 検索結果の残し方

実行したコマンドとヒット件数を控えておく。変更後に同じコマンドを再実行し、件数の比較を完了報告に載せる。検索できなかった範囲（別リポジトリ、外部の利用者、データベースに保存された値）は「未確認」として分けて書く。
