# 削除するとき

ファイル・関数・コンポーネント・アセット・CSS の宣言・ペイロードのフィールドを消すときに読む。

## 消してよいのは参照が 0 件のものだけ

`rules/search.md` の検索で、**定義そのものを除いた参照**が 0 件のものだけを削除する。名前で検索すると、定義している行は必ずヒットする。それ以外のヒットを 1 件ずつ見て、参照でないこと（同名の別物、コメントでの言及など）を確かめる。ヒットが残っている場合は、先に参照側をどうするか（一緒に消す・置き換える・残す）をユーザーに確認する。「たぶん使われていない」で消すと、壊れるのは検索しなかった場所で、発見が遅れる。

複数のものをまとめて消す場合は、1 件ずつ判定する。一覧のうち 1 件でも参照が残っていれば、その 1 件は外して報告する。

## ペイロードからフィールドを落とすとき

API のレスポンス、ハイドレーションに渡すデータ、イベントのペイロードなどからフィールドを落とす前に、**そのフィールド名で読み手を検索する**。型で optional（`field?: T`）として受けている読み手は、フィールドが消えてもコンパイルが通り、実行時に既定値へ黙って切り替わる。読み手が見つかったら、フィールドが無いときにその読み手がどう振る舞うかを確かめてから落とす。

別リポジトリやモバイルアプリなど、検索の届かない読み手がありうる API は、削除を「未確認」として報告し、ユーザーの判断を待つ。

## CSS の宣言を消すとき

スタイルを移行・整理する過程で宣言を落とす前に、そのプロパティがグローバルなリセット（`*` や要素セレクタへの一括指定）に含まれていないかを確かめる。リセットで別の値が当たっている場合、宣言を消すと既定値ではなくリセットの値に戻り、見た目が変わる。含まれていれば宣言は残す。

## 「無いこと」を根拠にした削除

「この導線はもう無いので、関連コードを消す」という判断は、`rules/search.md` の「『無い』と結論づける前に」を満たしてから行う。定数のキー名だけで導線の有無を判断して消すと、現行の画面が使っているコードを消すことになる。

## 削除後の確認

- 削除した名前の再検索が 0 件であること
- typecheck・lint・テストが通ること
- export を削除したならビルドが通ること
- アセットを削除したなら、そのアセットを表示していた画面を開いて表示が崩れていないこと（参照が文字列で組み立てられていると検索に掛からないため）
