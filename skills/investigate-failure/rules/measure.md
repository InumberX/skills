# 変更の前後を比べるとき

変更によって速くなったか、遅くなったか、件数や値が変わったかを、ローカルで比べるときに読む。

## 交互に実行して、ペアで比べる

変更前（A）と変更後（B）を、それぞれまとめて連続で実行しない。A → B → A → B のように交互に実行し、隣り合う A と B を 1 つのペアにする。

まとめて実行すると、実行の順番と時刻が結果に混ざる。マシンの温度、ほかのプロセス、キャッシュの状態は時間とともに変わり、その変化が A と B の差に見える。

最初の 1 ペアは集計から外す。初回はファイルやビルドのキャッシュが温まっておらず、どちらが先に走ったかで大きく差が出る。

## 判定には、ペアの差の中央値と、符号のそろい方を使う

各ペアで B − A を計算し、次の 2 つを見る。

- **差の中央値**：外れ値に引きずられない
- **符号のそろい方**：B が速かったペアの数と、遅かったペアの数

符号がほぼ半々なら、中央値に差があっても、変更の効果ではなく揺らぎと区別できない。平均だけで判断しない。1 回の外れ値で平均が大きく動く。

## 回数と条件を報告する

報告には、ペアの数、実行したコマンド、マシンと条件（電源の接続、ほかに動かしていたもの）を添える。回数が少ない場合は、結論ではなく「差は見られなかった / 差の傾向があった」と書く。

## 計測できる場所を先に決める

計測を前提にした改善や Issue を書く前に、その数値をどこで読むかを確かめる。本番の計測値を読めない場合は、対象をローカルで計測できるものに限定してから書く。読めない数値を目標にすると、達成したかどうかを確かめられない。
