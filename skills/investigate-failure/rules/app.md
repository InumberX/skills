# アプリの挙動の不具合を調べるとき

## 確かめている相手が正しいかを先に見る

ローカルの修正が効いていないように見えるときは、コードを疑う前に、リクエスト先のホストを確かめる。ブラウザの開発者ツールのネットワーク欄や、アプリが読み込んでいる環境変数を見る。ローカルの画面が検証環境や本番の API を呼んでいれば、ローカルのサーバー側の修正は反映されない。その場合は、ローカルでの確認を打ち切り、修正を反映できる環境に切り替える。

同じ理由で、データベースやクラスタに接続して調べる前に、接続先の環境を出力して確定させる（`kubectl config current-context` と namespace、接続文字列のホストなど）。認証情報はその環境から都度取得し、別の環境のものを使い回さない。

## 表示されるはずのものが出ないとき

表示する側の実装を疑う前に、**その要素を消す、隠す、上書きする処理**が他に無いかを検索する。条件付きの描画、CSS の `display: none`、後から実行されるスクリプト、別のコンポーネントでの上書きなどである。表示側のコードが正しくても、別の場所で消されていることがある。

外部のツールやタグが出力した部分で問題が起きている場合は、その部分を生成しているのが、サーバー側の描画、クライアント側のスクリプト、外部ツールの管理画面の設定のどれかを先に特定する。修正するファイルは、それによって決まる。

## 値がずれているとき

数値のずれは、同じ操作を 2 回繰り返し、両方で再現することを確かめてから報告する。1 回だけのずれは、操作の手順や、データの更新のタイミングの違いであることが多い。

サーバーの状態に依存する表示は、変更リクエストの成功ではなく、その後の再取得の完了を待ってから値を確かめる。再取得の前に見ると、古い値を見ている。

## ローカルでだけ出る警告やエラー

コードを直す前に、起動のコマンドや構成（開発サーバーか本番ビルドか、使っている設定ファイル、拡張機能の有無）を変えて、再現するかを確かめる。開発サーバーにしか出ない警告や、ブラウザの拡張機能が原因のエラーは、コードを直しても消えない。

## Cookie やセッションの不具合

Cookie が消えない、ログイン状態が保たれない、といった不具合は、開発者ツールで該当する Cookie の Domain・Path・有効期限・`SameSite` / `Secure` 属性を確かめ、報告に添える。同じ名前の Cookie が Domain や Path 違いで複数あると、消したつもりの Cookie が残る。

## インストールやビルドの失敗

`npm install` などが失敗したら、復旧の操作（キャッシュの削除、lockfile の作り直し）をする前に、次を記録する。

- ランタイムとパッケージマネージャーのバージョン
- lockfile の差分（`git diff` で、意図せず書き換わっていないか）
- エラーメッセージの原文

復旧の操作をすると、失敗したときの状態が消えて原因を追えなくなる。

コマンドが見つからない、CPU の種類が違うといったエラーは、コマンドの実体（どこにあるか、どのアーキテクチャか）を確かめる。同じ名前のコマンドが複数の場所にあり、古いものが先に見つかっていることがある。

```bash
which -a <cmd>                # 同じ名前の候補をすべて出す
file -L "$(command -v <cmd>)"  # 実際に使われるもののアーキテクチャ（<cmd> は調べるコマンド名）
```
