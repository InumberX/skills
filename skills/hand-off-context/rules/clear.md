# clear の手順

保存された引き継ぎデータを削除する。削除は元に戻せないため、**必ず対象を示してユーザーの確認を得てから**削除する。

| 指定 | 削除するもの |
| --- | --- |
| なし | `.handoff/handoff.md` と `.handoff/metadata.json`（履歴は残す） |
| `--history` | 上記に加えて、`.handoff/history/` の中のファイルすべて |
| `--keep <n>` | `.handoff/history/` のうち新しい n 件を残し、それより古いもの（最新の `handoff.md` は残す） |

`--history` と `--keep` は同時に指定できない。

削除してよいのは `.handoff/` の中のファイルだけである。プロジェクトのソースコード、`.handoff/.gitignore`、`.handoff/` ディレクトリ自体は削除しない。`.gitignore` を残すのは、次の export までの間に `.handoff/` が Git の管理対象として現れないようにするため。

## 1. 削除対象を示す

**スクリプトを使う場合**：`handoff_tool.py clear`（必要なら `--history` または `--keep <n>`）を実行する。`--yes` を付けなければ何も削除せず、対象の一覧だけを出力する。

**手作業の場合**：上の表に従って対象のファイルを列挙する。`--keep <n>` では、履歴をファイル名（`invalid-` で始まるものは、それを除いた部分）の順に並べ、新しい n 件を除いたものを対象にする。ファイル名の先頭が UTC の日時なので、名前順が時系列順になる。

対象がなければ、削除するものがないことを伝えて終える。

## 2. 確認を得る

対象の一覧を示し、削除してよいかをユーザーに尋ねる。「clear して」という依頼そのものを確認とみなさない。どの範囲が消えるかを見たうえで判断してもらうため。

## 3. 削除する

確認が得られたら削除する。

- **スクリプトを使う場合**：手順 1 と同じ指定に `--yes` を付けて実行する
- **手作業の場合**：対象のファイルを 1 つずつ削除する。ワイルドカードやディレクトリごとの削除は使わない。対象外のファイルを巻き込まないため

削除できなかったファイルがあれば、残りの削除を止めて報告する。

## ユーザーへの報告

```text
引き継ぎデータを削除しました（2 件）
- .handoff/handoff.md
- .handoff/metadata.json
履歴（3 件）は残しています。
```
