# 開閉する UI（アコーディオン・全文表示・折りたたみ）

差分に、押すと領域が開いたり閉じたりするボタンが追加・変更された場合に読む。引用するのは HTML と WAI-ARIA が規定する属性名だけで、フレームワークやプロジェクトに依存しない。

## 開閉の状態と、開閉する先を属性で伝える

開閉するボタンには、次の 2 つを付ける。

| 属性 | 値 | 理由 |
| --- | --- | --- |
| `aria-expanded` | 開いているとき `true`、閉じているとき `false` | 見た目（矢印の向き、「閉じる」の文言）だけでは、スクリーンリーダーの利用者に状態が伝わらない |
| `aria-controls` | 開閉する領域の `id` | ボタンと、開閉で変わる領域の関係が伝わる |

ボタンの文言を「全文を表示」「閉じる」のように切り替えるだけでは足りない。文言が変わっても、それが開閉の状態であることは支援技術に伝わらない。

```tsx
// Bad — 状態が文言とアイコンにしか無い
<button type="button" onClick={toggle}>
  {isOpen ? '閉じる' : '全文を表示'}
</button>
```

```tsx
// Good — 状態と開閉する先を属性で伝える
<button type="button" aria-expanded={isOpen} aria-controls={bodyId} onClick={toggle}>
  {isOpen ? '閉じる' : '全文を表示'}
</button>
<div id={bodyId}>…</div>
```

## 確かめること

- **共通のボタン部品を経由している場合**、その部品が `aria-expanded` を受け取って描画先の要素に渡しているかを確かめる。部品が受け取らないと、呼び出し側で指定しても描画されない。部品に足す場合は、既にある ARIA 属性（`aria-controls` など）と同じ形で、同じ描画先に渡す
- **`aria-controls` の `id` が、描画される要素を指しているか。** 開閉する領域を条件付きで描画している場合、領域が無いときにボタンだけが残ると、存在しない `id` を指すことになる。ボタンを出す条件と、領域を描画する条件が揃っているかを見る
- **`id` が一意か。** 一覧の各項目に開閉がある場合、固定の文字列を使うと `id` が重複する。フレームワークの一意な ID を生成する仕組み（React の `useId` など）か、項目のキーから作る
- **ボタンが `button` 要素か。** `div` や `span` にクリック処理を付けただけでは、キーボードで操作できず、ボタンとしても読み上げられない。フォームの中に置く場合は `type="button"` を指定する（指定しないと送信ボタンになる）

## 指摘の重要度

状態が伝わらないことは、見た目では気づけないため、Should 以上で挙げる。プロジェクトの `rules/` にアクセシビリティの方針（対応レベルなど）があれば、そちらの重要度に従う。
