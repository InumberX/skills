# 置き場所の決め方

ルールは、**次に同じ作業をするときに読み込まれる場所**に置く。正しい内容でも、作業中に読まれない場所にあれば守られない。

## 判断の順番

ユーザーが置き場所を指定していないときに使う。上から順に確認し、最初に当てはまった場所に置く。

| 順 | 確認すること | 置き場所 |
| --- | --- | --- |
| 1 | 依頼する側（人）の書き方・進め方のルールか | どこにも書き込まない。ユーザーに示すだけにする |
| 2 | lint・typecheck・テストで検出できるか | ツールの設定、またはテストを追加する（提案する） |
| 3 | そのプロジェクトのパス・識別子・構成に依存するか | プロジェクトの `CLAUDE.md` / `AGENTS.md`、または `.claude/skills/<タスク>/` |
| 4 | 複数のプロジェクトで同じ内容になるか | 作業の手順なら共有のスキルリポジトリ、自分の好みや習慣ならユーザー単位の指示ファイル（Claude Code は `~/.claude/CLAUDE.md`、Codex は `~/.codex/AGENTS.md`）。どちらも提案する |
| 5 | 迷ったら | プロジェクト側に置く |

迷ったときにプロジェクト側へ置くのは、共有の場所に置いたものが特定のプロジェクトの事情に引きずられると、全プロジェクトに影響するため。共有の場所への昇格は、同じルールが 2 つ以上のプロジェクトに書かれた時点で検討すればよい。

## CLAUDE.md とスキルの使い分け

プロジェクトの中でも、置き場所は 2 つある。

| 置き場所 | 読み込まれ方 | 向いているルール |
| --- | --- | --- |
| `CLAUDE.md` / `AGENTS.md` | 常に読み込まれる | どの作業でも守ること。ブランチ・コミットの規約、触ってはいけない場所など |
| `.claude/skills/<タスク>/`（Codex は `.agents/skills/<タスク>/`） | そのタスクのときだけ読み込まれる | 特定の作業でだけ必要な手順。レビューの観点、特定画面の実装手順など |

特定の作業でしか使わないルールを `CLAUDE.md` に足し続けると、常に読み込まれる量が増え、どのルールも目立たなくなる。該当するタスクのスキルがリポジトリ内にあれば、そちらの `rules/` に書く。プラグインとして導入したスキルは、リポジトリの外（導入元の共有リポジトリ）が実体なので、書き込まずに提案する。導入先のファイルを直接書き換えても、更新のたびに消える。

`CLAUDE.md` と `AGENTS.md` の両方がある場合は、プロジェクトが規約の本体を置いている方に書く。片方がもう一方を読み込むだけ（`@AGENTS.md` の 1 行など）なら、読み込まれる側が本体である。両方に書くと、片方だけ更新されて食い違う。

## 作業リポジトリの外に置くとき

共有のスキルリポジトリ、別プロジェクト、ユーザー単位の指示ファイルは、今の作業の変更に混ぜない。追記する文面と置き場所（リポジトリ・ファイル・節）を報告に書き、ユーザーの判断を待つ。ユーザーが最初からその場所を指定していた場合は、書き込んでよい。

## 書き込むときの注意

- 関連するルールの近く（同じ節）に追記する。末尾に足し続けない
- 既存の書式（箇条書きか表か、文体）に合わせる
- 秘密情報（トークン、パスワード、接続文字列）や個人情報を、ルールや例に含めない
